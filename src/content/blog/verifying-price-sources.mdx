date: 2026-07-21

If you are building anything on Robinhood Chain that touches a stock token price, you have a choice of sources and no obvious reason to prefer one. An explorer API returns a price in one HTTP call. A Chainlink feed takes an ABI, an address and a decimals field. The convenient one is very tempting.

We checked whether they agree. They frequently do not, and the direction of the error is not small.

## The method

Two sources, same moment, same tokens.

**Source A — the oracle.** Call `latestRoundData()` on the Chainlink aggregator for each token, scale by the feed's `decimals`, and keep `updatedAt`. This is the price Robinhood's own oracle documentation points at, the price our NAV oracle reads, and the price every value-bearing path in our contracts uses.

**Source B — the explorer.** Read `exchange_rate` from the Blockscout token API.

The feed directory has 56 entries, 51 of them USD-quoted, of which about 32 map to stock tokens — so roughly a third of the registry has a feed at all. Of those, 30 also had an explorer price. That is the comparison set.

## The result

**17 of 30 differed by more than 2%.** The worst cases:

| Token | Chainlink | Explorer | Difference |
|---|---|---|---|
| CRWV | $78.64 | $11.24 | **−85.7%** |
| IONQ | $35.35 | $45.77 | +29.5% |
| COIN | $176.81 | $210.42 | +19.0% |
| MU | $973.79 | $885.93 | −9.0% |
| CRCL | $71.72 | $65.29 | −9.0% |
| MSTR | $101.15 | $92.32 | −8.7% |

CRWV is the one to sit with. An eighty-six percent error is not drift or staleness — it is a different number about a different thing. Anything that priced a position, sized a trade, or computed a portfolio value from that field got an answer that was wrong by a factor of seven.

The knock-on effect is worth spelling out: an explorer's market-cap column is supply times its own price. Where the price is wrong, the market cap is wrong by the same factor. CRWV's real onchain market capitalisation was around $417k, not the $59.6k reported.

To be fair to the convenient source: on well-covered tokens it was fine. AMD came back at $540.59 against Chainlink's $542.37, SNDK at $1,569.28 against $1,572.49, ASML and ORCL matched to the cent. The failure is not uniform, which is exactly what makes it dangerous — spot-checking three tokens would have told you everything was fine.

## Staleness is normal, and must be visible

While reading the feeds we also kept `updatedAt`. Observed ages at the same instant ranged from **0.0 hours to 6.3 hours** — GOOGL 6.3h, SLV 5.5h, AMZN 5.3h.

This is not a malfunction. Robinhood's stock feeds update 24/5 with a deviation threshold and a long heartbeat, so a quiet stock simply does not tick. Outside US market hours they freeze entirely: the last traded price, accurate but not live.

The mistake is not the staleness. The mistake is displaying a stale price as though it were current, or worse, transacting on one. Basquets treats freshness as a first-class condition — `nav()` returns the last known value with a `fresh` flag, while `navStrict()`, which every value-bearing code path uses, reverts unless every component passes every check. Failing closed is the whole design.

## What to actually do

**Read the oracle your contracts read.** If a value can move money, derive it from the same source the settlement logic uses. A second source that disagrees is not redundancy, it is ambiguity.

**Treat explorer data as indicative.** It is excellent for holder counts, transfers and supply — indexed facts, not derived prices. Use it for discovery, not for valuation.

**Carry the timestamp everywhere.** A price without an age is not a price. Every surface that shows one should show how old it is, and every path that acts on one should refuse when it is too old.

**Check coverage before you design.** Only about a third of the stock token registry has a Chainlink feed today. If your product needs a price for all 96, the feed directory alone will not get you there, and the gap has to be filled with something you can defend — pool state you read yourself, not a number you found.

We are building an index protocol on these assets, which means every one of these failure modes eventually becomes our problem. Publishing the check is cheaper than discovering it in production.

All figures measured 21 July 2026 against `https://rpc.mainnet.chain.robinhood.com` and the public
Blockscout API. Both sources are live and the comparison is reproducible.

We apply this to ourselves: every price on the [stock token dashboard](/stocks) is tagged with the
source it came from, and a token we cannot price from a source we trust shows no price at all.
